请根据以下示例和输入，对候选回答进行结构化语义覆盖评分。 
输入： 
1. 标准 rm_schema 
2. 候选回答 candidate 

其中rm_schema的构成是: 
- factors：环境语义约束（事件类型 / 位置 / 具体描述）;
- ego_context：自车状态约束;
- actions：横向动作 / 纵向动作 / 行为目标
 - temporal：顺序要求; 
 
 你的任务是： 根据 rm_schema 评价 candidate 的语义覆盖程度。 
 允许同义表达，不要求逐字匹配。 只评分，不生成建议。 
 严格输出： {"c":[0.0],"lat":0.0,"lon":0.0,"q":0.0,"x":0.0}. 
 
 规则： 1. c（factor coverage） 对 rm_schema 中每个 factor 单独评分，输出 list，与 factors 顺序一致： 
 - 0.0 = 未覆盖 / 位置错误 / 事件类型错误 / 完全语义错误 / factor mixing;
- 0.5 = 位置 + 事件类型正确，但具体描述缺失、泛化，或写成同类子类型;
- 1.0 = 位置 + 事件类型 + 具体描述正确.

 补充： 
 - 每个 factor 必须独立匹配，禁止跨因素借分。 
 - candidate 只提到某一个 factor 时，其他未提到的 factor 必须为 0。 
 - 方向泛化允许 0.5（左前方→前方）。 - 方向错误必须 0.0（左前方→右前方）。 
 - 具体描述完整匹配：1.0。 
 - 具体描述缺失或泛化：0.5。 
 - 同一位置和事件类型下，同类子类型错误：0.5，例如右前方豁口盲区写成右前方车辆遮挡盲区。 
 - 完全语义错误：0.0，例如车辆停靠写成车辆缓慢行驶。 
 -- 1. factor 匹配必须同时绑定“位置 + 事件类型 + 具体描述”。若 candidate 中只有具体描述相同，但位置不同，不能匹配该 factor。 
 - 若 candidate 把一个 factor 的具体描述放到另一个 factor 的位置上，属于 factor mixing，相关 factor 均记 0.0。 
 - 例：rm_schema=[左前方车辆遮挡盲区, 右前方豁口盲区]，candidate=左前方豁口盲区，则 c=[0.0,0.0]，不是 [0.0,1.0]。 
 --2. lat（lateral） 横向动作评分： - 0.0 = 错误或冲突 - 0.5 = 部分匹配 - 1.0 = 正确. 若横向为空，默认保持。 保持 / 左换道 / 左避让 / 右换道 / 右避让 为不同动作。 
 --3. lon（longitudinal） 纵向动作 + 行为目标评分： - 0.0 = 错误或冲突 - 0.5 = 部分匹配 - 1.0 = 正确 若纵向为空，默认匀速。 加速 / 减速 / 匀速 / 停车 为不同动作。 
 --4. q（quality） 表达质量： - 0.0 = 关键词堆砌 / 模板 / 重复 / 难理解 - 0.5 = 可理解但表达一般 - 1.0 = 自然清晰 
 --5. x（conflict / hallucination） 明显冲突或幻觉惩罚： - 0.0 = 无 - 0.5 = 轻微 - 1.0 = 严重 若 candidate 引入 rm_schema 中不存在的关键语义内容，则记 conflict，包括： - 新的交通参与者 - 新的障碍 - 新的风险 - 新的交通信号 - 新的约束 - 新的动作意图 - factor mixing 普通修饰词不算 conflict，例如： 颜色、程度副词、轻微描述扩展。 严格只输出 JSON，不输出解释。
